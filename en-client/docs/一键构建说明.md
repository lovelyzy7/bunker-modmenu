
# 一键构建说明

## 最简用法（推荐）

| 想做什么 | Windows | WSL / Git Bash |
|---|---|---|
| **构建（自动识别 APK）** | 双击 `build.bat` | `bash build.sh` |
| 只构建私服补丁版 + 菜单 | 双击 `build_patched.bat` | `bash build_patched.sh` |
| 指定某个已打补丁的 APK | `build.bat --apk "D:/xxx.apk"` | `bash build.sh --apk /path/xxx.apk` |

`build.bat` / `build.sh` 会自动：

1. 扫描 `resources/`、客户端目录、`../../resources`（共享 APK 目录）里的 APK
2. 按文件名判断是**原版**还是**私服补丁版**（含 patched/private/lunar → 补丁版），优先选补丁版
3. 编译菜单 → 解包 → 注入 → 打包 → 对齐 → **用 `keys/` 里的固定密钥签名**
4. 打印成品路径、SHA256、**签名证书 SHA-256**（确认与其他版本一致）

需要指定某个 APK 时：`build.bat --apk "D:/xxx.apk" --target patched`

> 编码说明：`build.bat` 已内置 `chcp 65001` + `set PYTHONUTF8=1`，控制台/日志/重定向统一 UTF-8，中文不会乱码。

# 一键构建说明

> 改完 `modmenu/` 里的任何东西（Java/C++/标题/图标），运行对应脚本即可得到成品 APK。
> 全程自动：编译菜单 → 提取 smali/so → 解包目标 APK → 注入 → 打包 → 对齐 → 签名。

---

## 两个入口

| 用途 | Windows | WSL / Git Bash |
|------|---------|----------------|
| 私服补丁版 + 菜单 | 双击 `build_patched.bat` | `bash build_patched.sh` |

成品输出到 `dist/`：
- `dist/nier-mod-menu-original.apk`
- `dist/nier-mod-menu-en-patched.apk`
（带 `--tag v1.0.2` 时追加为 `...-original-v1.0.2.apk`）

## 前置条件（一次性）

| 项 | 说明 |
|----|------|
| JDK 17 | 一键脚本会从 `tools/toolpaths.json` 的 `java_home` 读取，或自动用环境变量 |
| Android SDK + NDK | `android_home` 指向 SDK（NDK 26.x 已装即可） |
| apktool.jar | `apktool_jar` 指向 apktool（也可放 `tools/apktool.jar`） |
| 输入 APK | 原版与私服版，放在 `../resources/`（自动扫描）或在 `tools/targets.json` 指定 |
| 签名密钥 | 归档的 `archive/keys/nier.keystore`（alias `nier` / 密码 `nier123456`） |

## 配置文件

- `tools/toolpaths.json` — 本机工具路径（**本地文件，不入库**）。模板见 `tools/toolpaths.example.json`：复制为 `toolpaths.json` 后按需填写，留空项自动探测
- `tools/targets.json` — 输入 APK 路径 + 扫描目录，例如：
  ```json
  {
    "original": "../resources/NieR Re[in]carnation 3.7.1_EN.apk",
    "patched":  "../resources/patched-local-6.apk",
    "search_dirs": ["../resources", "."]
  }
  ```
  配置路径不存在时，会自动在 `search_dirs` 里按文件名特征找：
  原版匹配 `*3.7.1*EN*.apk`；私服版匹配 `*patched*.apk`。

## 交互问答（回车即最佳路径）

脚本会"智能判断 + 确认"，全部直接回车即可：
```
输出文件名后缀 tag（可留空，如 v1.0.2） [  ]         ← 回车跳过
modmenu/ 没有新改动，跳过编译？（可省约 30 秒） [Y/n]  ← 回车=跳过编译
检测到目标 APK 的解包缓存（复用可省约 3 分钟），复用？ [Y/n] ← 回车=复用
检测到手机，是否安装到设备？ [y/N]                     ← 回车=不安装
```

## 命令行参数（可选，进阶/无人值守）

| 参数 | 说明 |
|------|------|
| `--yes` | 所有提问取默认值（推荐给快捷方式/批处理） |
| `--no-input` | 非交互模式（错误即退出，适合 CI） |
| `--no-build` | 跳过 Gradle 编译，用已有 `app-debug.apk` |
| `--menu-apk <路径>` | 直接用指定的菜单 APK（跳过编译） |
| `--apk <路径>` | 直接指定输入 APK（覆盖 targets.json） |
| `--out <路径>` | 指定输出 APK |
| `--tag vX.Y` | 输出文件名后缀 |
| `--fresh` | 强制重新解包目标 APK（不用缓存） |
| `--work <目录>` | 指定解包工作目录 |
| `--auth-dynamic` | auth 地址动态化（注入 `AuthHost`，引継ぎ/登录页可热切换；见 [`EN-auth动态化说明.md`](EN-auth动态化说明.md)） |
| `--auth-host <host[:port]>` | auth 默认地址（配合上一项；不填=自动探测，只写它也会自动开启动态化） |

示例：
```bash
bash build.sh --yes --tag v1.0.2               # 无人值守，出带版本号的成品
bash build_patched.sh  --fresh                 # 强制重新解包私服版
build.bat --auth-dynamic --auth-host 192.168.2.6:3000   # + auth 地址动态化
python3 tools/build_all.py --target original --no-build   # 只重注入（菜单没改）
```

## 流程详解（4 步）

1. **编译菜单 + 提取**：Gradle 编译 `modmenu/` → `app-debug.apk`；apktool 解包 → `build/menu_apktool/`（smali + `libniermenu.so`）
2. **解包/复用目标 APK**：按"路径+大小+mtime"指纹判断缓存（`build/work_<target>/`）
3. **注入**：菜单 smali（44 文件）→ 最高序号 smali 目录；`libniermenu.so` → `lib/arm64-v8a/`；清单加悬浮窗权限 + Launcher service；启动 Activity 注入 `Main->Start`（全部幂等，可重复执行）
4. **打包签名**：`apktool b` → `zipalign` → `apksigner`（v1+v2+v3）→ `verify` → 输出到 `dist/`，并打印大小与 SHA256

## 耗时参考

| 场景 | 耗时 |
|------|------|
| 首次全量（编译菜单 + 解包 250MB APK + 重建签名） | 约 8~12 分钟 |
| 只改菜单（复用解包缓存） | 约 2~3 分钟 |
| 只换图标/标题等，且 `--no-build` + 缓存 | 约 1 分钟 |

## 常见问题

| 现象 | 处理 |
|------|------|
| 提示"未找到 X 输入 APK" | 把 APK 放到 `../resources/`，或改 `tools/targets.json` |
| 提示"未找到 apktool.jar / build-tools" | 在 `tools/toolpaths.json` 填对路径 |
| Gradle 编译失败 | 看 `build/logs/` 最新日志；确认 JDK/NDK 与 `toolpaths.json` 一致 |
| 安装失败（签名冲突） | 先卸载手机上的旧版，再重试 |
| 想从零来过 | 删掉 `build/work_<target>/` 后加 `--fresh` 重跑 |
| 菜单装到手机没生效 | 确认已授予悬浮窗权限；完全关闭游戏重开 |
| 换游戏版本 | 需重新 dump 偏移并更新 `modmenu/app/src/main/jni/Main.cpp` 后再构建 |

## 注意

- `dist/`、`build/`、`logs/` 都已在 `.gitignore` 中排除，不会污染仓库
- 每次运行都会在 `build/logs/` 留一份带时间戳的日志，便于排查
- 重签名后的 APK 与官方不同，**必须卸载旧版才能安装**

## 编码 / 乱码说明（重要）

- `build_*.bat` 已内置 `chcp 65001` + `set PYTHONUTF8=1`：**控制台 / 日志文件 / 输出重定向统一 UTF-8**，中文不会再乱码。
- `tools/_common.py` 在 Windows 上会再兜底一次（自动 `SetConsoleOutputCP(65001)` 并把 stdout/stderr 固定为 UTF-8），
  因此直接运行 `python tools\build_all.py` 也不会乱码。
- 日志在 `build/logs/*.log`（UTF-8）：用 VS Code / 记事本直接打开即可；若在老式 cmd 里用 `type` 查看，先执行一次 `chcp 65001`。
- 仓库文本文件统一 **UTF-8（无 BOM）**：`.bat` 为 CRLF，其余为 LF（见仓库根 `.gitattributes`）。
