## 1. 工程是什么

本工程基于 **LGL Mod Menu 4.0**（悬浮窗 + JNI）改造，专门用于
`com.square_enix.android_googleplay.nierspww`（NieR Reincarnation 3.7.1）。

| 功能 | 控件 | 默认值 |
|------|------|--------|
| 伤害倍率 | 滑块 1~333 | 333 |
| 防御倍率 | 滑块 1~333 | 333 |
| 角色技能无CD | 开关（默认开） | 开 |

一个"功能"的完整链路是：

```
菜单 UI（Java 悬浮窗）
   ↓ 用户拖动滑块/点开关
Preferences.Changes(...)   （Java native 方法）
   ↓ JNI
Main.cpp 的 Changes()      （把值存进全局变量）
   ↓ 游戏运行时每次调用被 Hook 的函数
Hook 函数读取全局变量 → 修改参数/返回值/跳过原逻辑
```

**记住这条链路**：菜单只负责"改一个变量"，真正生效靠 Hook 函数在游戏运行时读取该变量。

## 3. 运行原理（先懂这个）

### 3.1 启动时序

```
游戏主 Activity.onCreate()
   └─(注入的那行) invoke-static Main->Start(context)
        ├─ System.loadLibrary("niermenu")     ← 加载我们的 .so
        │     └─ JNI_OnLoad（Setup.cpp）
        │           ├─ RegisterMenu()          注册 Icon/Init/GetFeatureList…
        │           ├─ RegisterPreferences()   注册 Changes()
        │           └─ RegisterMain()          注册 CheckOverlayPermission()
        ├─ CrashHandler.init()                 注册崩溃捕获
        └─ CheckOverlayPermission()
              ├─ 无权限：提示 + 跳转系统设置 + 3 秒后退出游戏
              └─ 有权限：startService(Launcher)
                    └─ Launcher.onCreate()
                          └─ new Menu(context) → ShowMenu()
                                └─ 通过 JNI 调 Init / Icon / GetFeatureList / SettingsList
                                      └─ 悬浮窗显示出来
```

### 3.2 native 库自己的启动

`Main.cpp` 末尾：

```cpp
__attribute__((constructor))   // 库被 dlopen 时自动执行
void lib_main() {
    pthread_t ptid;
    pthread_create(&ptid, NULL, hack_thread, NULL);  // 新线程里做 Hook
}
```

`hack_thread` 会循环等待 `libil2cpp.so` 出现，然后解析函数地址、挂 Hook。
**注意**：Hook 在库加载后立刻开始，可能早于游戏逻辑，所以 Hook 函数内部
必须自己处理"变量还没被菜单设置"的情况（本工程用全局变量的初始默认值解决）。

### 3.3 设置是怎么保存的

`Preferences.java` 提供 `loadPrefInt / loadPrefBool` 等：

- 如果菜单里勾选了 **Save feature preferences**（设置页 -1 项），重启后会自动
  把保存的值通过 `Changes()` 推给 native；
- 没勾选时，滑块在**用户第一次拖动**前不会调用 `Changes()`——
  这解释了"为什么滑块默认值必须在 C++ 里写好"（本工程默认 333）。

## 4. Java 层逐文件详解

### 4.1 `Main.java` —— 入口

```java
public class Main {
    static {
        System.loadLibrary("niermenu");   // ★ 库名必须与 Android.mk 的 LOCAL_MODULE 一致
    }

    private static native void CheckOverlayPermission(Context context);

    public static void Start(Context context) {     // 注入到游戏 onCreate 的就是这一句
        CrashHandler.init(context, false);          // 崩溃日志
        CheckOverlayPermission(context);            // 权限检查 → 启动服务
    }

    public static void StartWithoutPermission(Context context) { ... } // 方法2用（无悬浮窗）
}
```

- **注入点**：游戏主 Activity 的 `onCreate` 里一行 smali：
  `invoke-static {p0}, Lcom/android/support/Main;->Start(Landroid/content/Context;)V`
- 库名三处必须一致：`Android.mk` 的 `LOCAL_MODULE`、这里的 `loadLibrary`、
  注入后 APK 里的 `lib/arm64-v8a/lib<名字>.so`。

### 4.2 `Launcher.java` —— 悬浮菜单服务

- 继承 `Service`，在 `onCreate()` 里创建菜单并显示；
- 每秒检查一次"是否还在前台游戏中"（`importance != 100` → 隐藏菜单），避免在桌面/其他应用上乱显示；
- `onTaskRemoved` 里自动 `stopSelf()`，防止后台常驻耗电；
- 在游戏 `AndroidManifest.xml` 里注册（注入流程自动完成）：
  ```xml
  <service android:name="com.android.support.Launcher" android:enabled="true"
      android:exported="false" android:stopWithTask="true" />
  ```

### 4.3 `Menu.java` —— 菜单 UI（★ 最常改外观的文件）

**顶部「菜单外观配置区」**（改颜色/尺寸/位置都在这里）：

```java
int TEXT_COLOR = Color.parseColor("#82CAFD");        // 功能名颜色
int MENU_BG_COLOR = Color.parseColor("#EE1C2A35");   // #AARRGGBB（前两位=透明度）
int MENU_WIDTH = 290, MENU_HEIGHT = 210;             // 面板尺寸(dp)
int ICON_SIZE = 45;                                  // 悬浮图标大小
float ICON_ALPHA = 0.7f;                             // 图标透明度
int ToggleON = Color.GREEN, ToggleOFF = Color.RED;   // 开关颜色
int SeekBarColor / SeekBarProgressColor = ...        // 滑块颜色
```

**功能列表解析**（`featureList()`）：把 native 返回的字符串数组逐条解析。
格式是 `(可选编号)_类型_名字_参数…`：

```java
String[] str = feature.split("_");
if (TextUtils.isDigitsOnly(str[0])) {   // 开头是数字 → 显式功能号
    featNum = Integer.parseInt(str[0]);
    feature = feature.replaceFirst(str[0] + "_", "");
} else {
    featNum = i - subFeat;              // 否则自动编号（不计数项不占号）
}
switch (strSplit[0]) {
    case "Toggle":   Switch(...);   break;
    case "SeekBar":  SeekBar(..., Integer.parseInt(strSplit[2]), Integer.parseInt(strSplit[3])); break;
    ...
}
```

**控件 → native 回调**：所有控件最终都走 `Preferences.changeFeatureXxx(...)`，
例如滑块：

```java
seekBar.setOnSeekBarChangeListener(new SeekBar.OnSeekBarChangeListener() {
    public void onProgressChanged(SeekBar seekBar, int i, boolean z) {
        Preferences.changeFeatureInt(featName, featNum, i < min ? min : i);  // → Changes()
    }
});
```

> 本工程把滑块初始进度改成了 max（`setProgress((loadedProg == 0) ? max : loadedProg)`），
> 所以打开菜单就看到默认值 333，并且 native 里的默认值也是 333，两者一致。

### 4.4 `Preferences.java` —— 偏好保存与 native 桥

```java
public static native void Changes(Context context, int featNum, String featName,
                                  int value, long Lvalue, boolean isOn, String inputText);

public static void changeFeatureInt(String featureName, int featureNum, int value) {
    Preferences.with(context).writeInt(featureNum, value);   // 存 SharedPreferences
    Changes(context, featureNum, featureName, value, 0, false, null);  // 通知 native
}
```

- **负数功能号是菜单自己的设置项**：`-1` 保存偏好、`-3` 自动高度、`-6` 关闭设置；
  想加自定义设置项就在 `SettingsList()`（C++）里加负数编号，并在
  `Main.cpp` 的 `Changes()` `default:` 分支处理。
- 偏好文件保存在应用私有目录，名为 `<包名>_preferences`。

### 4.5 `MainActivity.java` / `CrashHandler.java`

- `MainActivity`：只在"方法 2（把菜单自己当启动 Activity）"时需要；普通注入不用改。
- `CrashHandler`：注册全局未捕获异常处理器，崩溃时把堆栈 + 设备信息写到
  `/storage/emulated/0/Documents/mod_menu_crash_时间.txt`，方便反馈问题。

## 5. JNI 层逐文件详解

### 5.1 `Menu/Setup.cpp` —— 标题与 JNI 注册

```cpp
void Init(JNIEnv *env, jobject thiz, jobject ctx, jobject title, jobject subtitle) {
    // 大标题（支持 HTML）
    setText(env, title, OBFUSCATE("<b>NieR Reincarnation · Lunar-Tear</b>"));
    // 副标题（marquee 滚动）
    setText(env, subtitle, OBFUSCATE("<b><marquee>Mod Menu v1.0 | ...</marquee></b>"));
    // 启动 Toast
    Toast(env, ctx, OBFUSCATE("Mod Menu 已加载"), ToastLength::LENGTH_SHORT);
}
```

文件下半部分是 `RegisterMenu / RegisterPreferences / RegisterMain`，
把 C++ 函数注册到 Java 类；**新增 native 方法时必须在这里加一行**：

```cpp
{OBFUSCATE("方法名"), OBFUSCATE("(参数签名)返回值签名"), reinterpret_cast<void*>(CppFunction)},
```

### 5.2 `Menu/Menu.cpp` —— 图标与设置页

- `Icon()`：返回 **base64 PNG** 字符串（悬浮图标）。换图标：
  准备 128×128 PNG → 转 base64 → 替换字符串。
- `IconWebViewData()`：返回 GIF URL 或 `data:image/gif;base64,...`，返回 `nullptr` 则用普通图标。
- `SettingsList()`：设置页（齿轮）条目列表，语法同功能列表；
  已内置`-1 保存偏好 / -3 自动高度 / -6 关闭设置`。

### 5.3 `Menu/Jni.cpp` —— 辅助功能

- `Toast()` 弹提示、`setDialog()` 弹对话框；
- `CheckOverlayPermission()`：先判断系统版本（>=23 需要运行时授权），
  `Settings.canDrawOverlays()` 为 false 时提示并跳转设置页，然后退出游戏（让用户重开）；
- `startService()`：启动 `com.android.support.Launcher`。
- **注意**：如果游戏清单里没有 `SYSTEM_ALERT_WINDOW` 权限，设置页里悬浮窗开关会是灰的
  （注入脚本已自动加上）。

### 5.4 `Main.cpp` —— ★ 核心文件（功能与 Hook 都在这里）

#### (1) 全局配置变量（菜单会改、Hook 会读）

```cpp
static int  g_dmgMul   = 333;    // 伤害倍率
static int  g_defMul   = 333;    // 防御倍率
static bool g_skillNoCd = true;  // 角色技能无CD
```

#### (2) `GetFeatureList()` —— 菜单显示什么

```cpp
const char *features[] = {
        OBFUSCATE("Category_战斗功能"),          // 分类标题（不占功能号）
        OBFUSCATE("1_SeekBar_伤害倍率_1_333"),   // 功能号 1：滑块 1~333
        OBFUSCATE("2_SeekBar_防御倍率_1_333"),   // 功能号 2
        OBFUSCATE("3_True_Toggle_角色技能无CD"), // 功能号 3：默认开启的开关
};
```

#### (3) `Changes()` —— 菜单回调（把值存进变量）

```cpp
switch (featNum) {
    case 1: g_dmgMul = (value >= 1) ? value : g_dmgMul; ... break;
    case 2: g_defMul = (value >= 1) ? value : g_defMul; ... break;
    case 3: g_skillNoCd = boolean; break;
}
```

> 功能号必须和 `GetFeatureList` 里的编号一一对应；显式编号（`1_`、`2_`…）最稳。

#### (4) Hook 函数的标准写法

```cpp
// 1. 声明"原函数"指针（HOOK 宏会填好它）
void (*old_Func)(void *self, int x);

// 2. 写自己的函数：想改什么就改什么
void Func(void *self, int x) {
    if (g_someFlag) x = x * 2;     // 改参数
    old_Func(self, x);             // 调原函数（也可以不调 = 跳过原逻辑）
}

// 3. 注册（在 hack_thread 里）
HOOK(targetLibName, str2Offset(OBFUSCATE("0x123456")), Func, old_Func);
```

`Includes/Macros.h` 提供的宏：

| 宏 | 作用 |
|----|------|
| `HOOK(库, 偏移, 新函数, 原函数指针)` | 挂钩并保留原函数 |
| `HOOK_NO_ORIG(库, 偏移, 新函数)` | 挂钩、不调用原函数 |
| `HOOKSYM / HOOKSYM_NO_ORIG` | 按符号名挂钩 |
| `PATCH(库, 偏移, "hex")` | 直接改内存（一条指令） |
| `MemoryPatch::createWithHex(...)` | 可开关的补丁（`.Modify()` / `.Restore()`） |

#### (5) `hack_thread()` —— 等库、解析地址、挂 Hook

```cpp
void *hack_thread(void *) {
    ElfScanner elf;
    do { sleep(1); elf = ElfScanner::createWithPath(targetLibName); } while (!elf.isValid());
#if defined(__aarch64__)
    // 先解析"辅助函数"（后面 Hook 里要调用它们）
    f_JoinParty   = (Fn_P1) getAbsoluteAddress(targetLibName, str2Offset(OBFUSCATE("0x3E6E3CC")));
    ...
    // 再挂 Hook
    HOOK(targetLibName, str2Offset(OBFUSCATE("0x3B0C980")), AtkDamageSetter, old_AtkDamageSetter);
    ...
#endif
}
```

## 7. 本游戏已有功能是怎么实现的

### 7.1 伤害倍率 / 防御倍率（同一个挂钩点）

- **挂钩点**：`FieldTurnBattleComputerSkillBehaviourAttackDamage` 的 setter
  （RVA `0x3B0C980`），这是"伤害结算字段"真正生效的位置。
- **逻辑**：
  ```cpp
  void *tgt = f_TargetActor(data);   // 取目标
  int tpid = pidOf(tgt);             // 目标阵营（0=我方，1=敌方）
  if (tpid == PLAYER_PID)            // 打的是我方 → 防御
      nv = v / g_defMul;
  else                               // 打的是敌方 → 伤害
      nv = min(v * g_dmgMul, 15 亿);
  ```
- **为什么需要"幂等历史"**：这个 setter 在**一次攻击内会被连续调用 8 次**
  （管线每步都"读字段→乘系数→写回"）。如果每次调用都乘倍率，就会变成
  ×倍率⁸（曾经实测 ×256 被放大到 ×2⁶⁴）。
  解决：记录"最近写过的值"，如果本次传入的值就是刚写进去的（说明是管线回读），
  就**不再缩放**。相关代码：`isReadBack()` / `markWrite()`。
- **上限**：结果 clamp 到 15 亿（游戏自身伤害上限），防止 int32 溢出变负数。

### 7.2 角色技能无CD

- **挂钩点**：`FieldTurnBattleSkillDynamicCurrentCooltime` 的 setter（RVA `0x3B11F10`）。
- **逻辑**：技能归属角色（`f_FromActor`）属于我方时，把写入的充能值
  强制替换为 **最大充能值**（`f_MaxCool`）→ 永远满充能 → 随点随放。

### 7.3 COMBO 最大 & 不断（已移除）

> 该功能已从菜单移除（不再挂钩 COMBO 相关函数）。
> 历史实现与偏移仅存档于 `docs/MOD制作记录.md` §3.7。

## 8. 教程 A：新增一个开关功能

以"无敌"（假设已找到判定函数）为例，**完整五步**：

**第 1 步：找偏移**
用 Il2CppDumper 的 `dump.cs` 搜函数名，取上方 `// RVA: 0x…`。
（怎么 dump、怎么定位见 `../docs/MOD制作记录.md`【3】【4】。）

**第 2 步：在 `Main.cpp` 加变量**

```cpp
static bool g_godMode = false;   // 无敌开关（默认关）
```

**第 3 步：写 Hook 函数并注册**

```cpp
// 原函数：bool IsInvincible(void* self)
bool (*old_IsInvincible)(void *self);

bool IsInvincible(void *self) {
    if (g_godMode) return true;          // 开了无敌 → 永远返回 true
    return old_IsInvincible(self);       // 否则走原逻辑
}

// 在 hack_thread() 里注册（放在其它 HOOK 后面）
HOOK(targetLibName, str2Offset(OBFUSCATE("0x1234567")), IsInvincible, old_IsInvincible);
```

**第 4 步：加菜单项 + 回调**

```cpp
// GetFeatureList 里追加
OBFUSCATE("5_Toggle_无敌"),

// Changes 里追加
case 5:
    g_godMode = boolean;
    break;
```

**第 5 步：构建 + 注入 + 验证**

```bash
bash build_patched.sh        # 或 Windows 双击 build_patched.bat
adb logcat -s Mod_Menu       # 看是否有 Changes[5] … 日志
```

## 9. 教程 B：新增一个滑块功能

以"移动速度倍率"为例（假设游戏用 `GetMoveSpeed` 返回速度）：

```cpp
static int g_speedMul = 1;

int (*old_GetMoveSpeed)(void *self);
int GetMoveSpeed(void *self) {
    int v = old_GetMoveSpeed(self);
    if (g_speedMul > 1) v = (int)((long long)v * g_speedMul);   // 用 long long 防溢出
    return v;
}
HOOK(targetLibName, str2Offset(OBFUSCATE("0x1234568")), GetMoveSpeed, old_GetMoveSpeed);
```

菜单项与回调：

```cpp
OBFUSCATE("6_SeekBar_移速倍率_1_10"),     // 1~10

case 6:
    g_speedMul = (value >= 1) ? value : g_speedMul;
    break;
```

> 改**返回值**的 Hook 不需要原函数也能工作，但保留原函数更安全
> （便于按原值缩放、也便于随时关掉功能）。

## 12. 调试与常见问题

| 现象 | 原因与处理 |
|------|------------|
| 没有悬浮图标 | 悬浮窗权限没给；或 `Main->Start` 没注入成功（检查游戏 smali 注入点） |
| 菜单能开但功能无效 | 功能号不匹配（`GetFeatureList` 编号 vs `Changes` case）；或开关默认值不对 |
| 滑块拖了没用 | 确认对应 case 已实现、Hook 已挂（`logcat` 有 `Changes[…]` 才有回调） |
| 游戏闪退 | 偏移失效（换了游戏版本）/ Hook 地址错 / 库名三处不一致；看 `logcat` 崩溃栈 |
| 数据全是 0 或异常 | 32 位溢出：乘倍数前先转 `long long` 并 clamp |
| 数值被放大成天文数字 | 挂到了"会被管线反复读写"的 setter 上：改用"一次调用点"或加幂等判断 |
| 换游戏版本后失效 | 重新 dump 偏移，更新 `Main.cpp` 里的 RVA，重新构建 |
| 构建报找不到 NDK/SDK | 配置 `tools/toolpaths.json`（模板 `tools/toolpaths.example.json`） |

常用命令：

```bash
adb logcat -s Mod_Menu                 # 只看菜单日志
adb logcat | grep -i -E 'Mod_Menu|DEBUG|FATAL'   # 崩溃排查
adb shell dumpsys package com.square_enix.android_googleplay.nierspww | grep version
```

## 14. 原版模板示例功能（各控件用法大全）

> 原版 LGL 模板自带一整套“控件演示”功能，完整代码在
> `en-client/archive/template/Android-Mod-Menu-cn-4.0.zip` 的 `app/src/main/jni/Main.cpp` 里（中文注释）。
> 本节把它们逐一讲清楚，可在本工程里直接照抄改造。
>
> **所有控件都只是 UI；真正做事的是 `Changes()` 收到的参数**，对应关系如下。

### 14.1 控件 → `Changes()` 参数对照

| 控件语法 | 触发时机 | `Changes()` 里拿到的值 |
|---|---|---|
| `Toggle_名字` / `True_Toggle_名字` | 开关切换 | `boolean` = 开/关 |
| `CheckBox_名字` | 勾选变化 | `boolean` |
| `ButtonOnOff_名字` | 按钮切换 | `boolean` |
| `Button_名字` | 点击一次 | `value = 0`（当作“触发信号”） |
| `SeekBar_名字_最小_最大` | 拖动 | `value` = 当前值 |
| `InputValue[_上限]_名字` | 输入框确认 | `value` = 整数 |
| `InputLValue[_上限]_名字` | 输入框确认 | `Lvalue` = 长整数 |
| `InputText_名字` | 输入框确认 | `text` = 字符串（需 JNI 转 `char*`） |
| `Spinner_名字_项1,项2` | 选择 | `value` = 选项索引（0,1,2…） |
| `RadioButton_名字_项1,项2` | 选择 | `value` = 索引 |
| `Category_` / `RichTextView_` / `RichWebView_` / `ButtonLink_` | 纯显示 | 无回调（不占功能号） |
| `Collapse_标题` + `CollapseAdd_xxx` | 折叠分组 | 子项按各自类型回调 |

> `SeekBar` 的 `value` 就是真实值；`Spinner/RadioButton` 是**索引**，需要自己映射成实际含义。

### 14.2 原版示例功能一览

| 原版功能 | 控件 | 实现思路 |
|---|---|---|
| 无敌 | `Toggle_无敌` | `MemoryPatch` 改函数头 → `Modify()` / `Restore()` 开关 |
| 开始无敌（30 秒） | `Button_…` | 按钮设 `btnPressed=true`，在 `Update` hook 里调用游戏函数 |
| 分数倍率 | `SeekBar_…_1_100` | hook `AddScore`，`old(x, score * scoreMul)` |
| 金币倍率 | `SeekBar_…_1_1000` | hook `AddCoins`，`old(x, count * coinsMul)` |
| 其余控件 | 各种 | 纯演示（观察 `Changes()` 收到的参数） |

### 14.3 可直接照抄的写法

**① 开关 + 内存补丁（原版“无敌”）**
```cpp
static bool g_noDeath = false;
MemoryPatch g_noDeathPatch;

// Changes():
case 0:
    if (boolean) g_noDeathPatch.Modify();    // 开：写入补丁
    else         g_noDeathPatch.Restore();   // 关：还原
    break;

// hack_thread():
g_noDeathPatch = MemoryPatch::createWithHex(
        il2cppBase + str2Offset(OBFUSCATE("0x偏移")),
        "C0 03 5F D6");     // ARM64: ret（示例）
```

**② 开关 + Hook 里读标志**
```cpp
static bool g_godMode = false;

bool (*old_IsInvincible)(void *self);
bool IsInvincible(void *self) {
    if (g_godMode) return true;         // 开
    return old_IsInvincible(self);      // 关 → 原逻辑
}
// hack_thread():
HOOK(targetLibName, str2Offset(OBFUSCATE("0x偏移")), IsInvincible, old_IsInvincible);
// Changes():
case 5: g_godMode = boolean; break;
```

**③ 按钮（一次性动作）**
```cpp
static bool g_btnPressed = false;

void (*old_Update)(void *self);
void Update(void *self) {
    if (g_btnPressed && self) {
        DoSomething(self);      // 调用游戏函数
        g_btnPressed = false;
    }
    old_Update(self);
}
// Changes():
case 6: g_btnPressed = true; break;
```

**④ 滑块（倍率）**
```cpp
static int g_scoreMul = 1;

void (*old_AddScore)(void *self, int score);
void AddScore(void *self, int score) {
    long long v = (long long)score * g_scoreMul;   // 先转 long long 防溢出
    return old_AddScore(self, (int)v);
}
// Changes():
case 2: if (value >= 1) g_scoreMul = value; break;
```

**⑤ 复选框 / 开关按钮**（与 Toggle 相同）
```cpp
case 7: g_flag = boolean; break;
```

**⑥ 下拉框 / 单选（拿到的是索引）**
```cpp
static int g_mode = 0;                     // 0=关闭, 1=模式1, 2=模式2

// Changes():
case 8: g_mode = value; break;             // value 是选项索引
```

**⑦ 输入数字 / 长整数 / 文本**
```cpp
static int  g_num = 0;
static long long g_lnum = 0;
static std::string g_text;

// Changes():
case 9:  g_num = value;  break;
case 10: g_lnum = Lvalue; break;
case 11: {
    const char *c = env->GetStringUTFChars(text, nullptr);
    g_text = c ? c : "";
    env->ReleaseStringUTFChars(text, c);
    break;
}
```

**⑧ 分组 / 说明 / 链接（纯 UI，无回调）**
```cpp
OBFUSCATE("Category_战斗功能"),
OBFUSCATE("RichTextView_<b>加粗</b> <font color='red'>彩色</font> 说明文字"),
OBFUSCATE("ButtonLink_官方链接_https://github.com/"),
OBFUSCATE("Collapse_高级选项"),
OBFUSCATE("CollapseAdd_Toggle_子开关"),
OBFUSCATE("Collapse_默认展开的分组_True"),
```

### 14.4 从原版示例迁移到本游戏

原版示例里的偏移（`0x107A3BC` 等）是**演示用占位地址**，必须换成实际游戏的 RVA：

1. 在 `dump.cs` 里找到目标函数（参考 `../docs/MOD制作记录.md`【3】【4】）
2. 把 `HOOK(targetLibName, str2Offset(OBFUSCATE("0x占位")), …)` 换成真实 RVA
3. 按 14.1 的对照表设计控件（建议用**显式编号**，与 `Changes()` 的 case 一一对应）
4. 跑一键脚本构建、装机验证

> 现成可参考的“真实实现”就是本工程第 7 节的四个功能；
> 原版示例偏“演示所有控件”，两者结合看能覆盖绝大部分场景。
